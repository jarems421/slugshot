# Slugshot Blender skill routing

Updated 2026-10-31. This is the decision guide for the isolated creature worktree. Read the [species record](catalog/index.md), [modelling lessons](blender-lessons.md) and [installation audit](install-audit.md) before changing a creature. The owner's current first-creature feedback is an open artistic problem; a passing Blender script does not approve its design.

The exact installed names in the tables are discoverable in `~/.agents/skills/` and `~/.claude/skills/`; the project skill is in the worktree's `.agents/skills/` and `.claude/skills/`. The two libraries' animation and rendering skills are deliberately distinct.

`H52` = headless Blender 5.2.3 with the EL scripts. `M` = installed ahujasid MCP for Blender, named `blender`, with a live Blender 4.5 or 5.2 scene. `B` = BlendRelay on a connected live scene, useful for selected mesh edits and checkpoints. `P` = local Python image-analysis script. `D` = planning/document review without Blender. EL's 67 source tests and a 5.2 disposable rig/render/export example passed; this is **not** a per-skill agent execution claim. RL's source contracts and 12 export regressions passed; most RL leaf recipes have not been executed locally. Fresh Codex and Claude sessions discovered sample skills and explicitly invoked SS. See the [audit](install-audit.md) for exact evidence.

The installed `blender` server currently exposes `get_addon_status`, `get_scene_info`, `execute_blender_code`, `look`, `generate_3d`, `search_assets`, `import_asset`, `disable_telemetry` and `record_trajectory_feedback`. RL recipes also list legacy tools such as `get_object_info` and `render_viewport_to_path`, which this server **does not expose**. Resolve those operations through current `get_scene_info`, `look` or reviewed `execute_blender_code` calls in a disposable scene; do not assume a recipe runs verbatim. The RL reference/wireframe helper stack requires OpenCV for several scripts; local Python has NumPy, SciPy and Pillow but **no `cv2`**, so those scripts are unavailable until that dependency is reviewed and installed. No GPU image-to-3D generator is configured. BlendRelay is a separate backend, not a drop-in replacement for RL MCP tool names. EL's human/R15 and RL's exact mascot recipes do not by themselves fit the custom Slugshot rig or original IP brief.

## How to select and work

1. Classify the request: original design, form/silhouette, local feature, surface look, deformation/motion, export/import, or evidence. Identify the failing view and the latest approved constraint. If the cause is unknown, inspect first.
2. Select **one primary skill** from the lifecycle table. Add a supporting skill only if the task crosses a real boundary, such as sculpt → retopology or rig → animation. Read only those `SKILL.md` files and any referenced section needed for this operation. Check the version, available MCP tool schema and local Python dependencies before acting.
3. Select one backend. Use existing Blender 4.5 headless project scripts for reproducible creature builds, EL with explicit Blender 5.2.3 for compatible procedures, `B` for a selected live-scene edit, or `M` for reviewed Python/live inspection and RL recipes. Confirm the open `.blend` is the intended scene. Never switch live backends mid-operation without saving and re-inspecting state.
4. Save a copy or BlendRelay checkpoint before geometry, rig or material edits. Preserve accepted source and renders. Apply a local correction to a local problem. On an existing scene, **do not run RL's generic world-reset step** or any script that clears the scene. Do not use strict 1:1 reconstruction against franchise references; only owner-approved original Slugshot source can be a source-locked target.
5. Render front, side, back and three-quarter views under consistent light. Check geometry, weights, UV/materials, animation frames and export as relevant. Compare visual output with the brief and previous accepted iteration. Diagnose repeated failures as possible modelling-method failures before another cosmetic pass. Record verified fixes in [lessons](blender-lessons.md); owner approval is the art gate.

For Codex and Claude Code, open `C:/Users/runni/slugshot-slug-pipeline` and describe the creature task normally, or invoke `$slugshot-blender-orchestrator` with the request. The router is the default entrypoint; exact source skill names below are for deliberate overrides. Run `python tools/slugs/check_skill_routing.py` to check catalogue coverage and `python tools/slugs/install_blender_skills.py --check` to verify installed copies. Keep normal build outputs ignored. For Roblox, use [Studio import checklist](studio-import.md); Blender FBX reimport cannot prove Studio playback.

## Known gaps and evidence boundary

- Legacy RL MCP command names are **not present** on the installed `blender` server. Test an equivalent current tool operation in a disposable scene before using a recipe that calls one.
- Individual skills have not all been run on Slugshot assets. Suite tests and a representative disposable example establish installation and some compatibility, not 58 end-to-end successes.
- Roblox Studio import and playback remain unverified for the first creature. An FBX roundtrip is an intermediate check.
