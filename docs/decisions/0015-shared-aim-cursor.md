# ADR 0015: Share the aiming point between the cursor HUD and firing

**Tight vibration / rims / sheen, 2026-11-01:** owner accepts the tighter translucent base. Replace broad UIScale breathing with constant-size geometry, a tiny held-ring tremor and light shimmer; keep aim independent. Full circles are continuous/unclipped. Fine inner/outer charcoal contours and a traveling reflection implement the follow-up request, without rotating targeting geometry. [Evidence/limits](../evidence/2026-11-01-tight-ring-rims.json).

**Simplification / full hold follow-up, 2026-11-01:** owner removes outer corner decorations and requests gentle sustained ring energy. Keep the accepted aim mark independent of the animated ring: no loading scale change, a small full-ring-only breath, softer blended intake, and a 0.14-second visual gate for decorative intake on tap fire. Source charge/firing time and pointer policy are unchanged. [Evidence/limits](../evidence/2026-11-01-simple-charge.json). Supersedes still full hold and busy loading effects below.

**Lobby art / pointer follow-up, 2026-11-01:** pointer visibility is enforced at `Last + 1000`, with a property-change re-enable guard and fresh menu exception. Verify it after competing late writes, not only immediately after the HUD callback. Reticle rendering now uses the lobby's charcoal/white hierarchy and purposeful gathering/closure; no rubber spring. Aim point, camera and shot rules remain shared/unchanged. [Source research](../research/charge-art-direction.md), [evidence/limits](../evidence/2026-11-01-ink-charge.json). Subjective acceptance remains open.

**White tension / sizing follow-up, 2026-11-01:** retain the accepted crosshair shape with exact 1.15 third-/1.22 first-person mode scaling. White native circular strokes with clipped gradient masks/rounded caps supersede the colored rectangular arc pieces. Preserve actual angular charge progress; contraction/stroke weight supplies loading tension and a damped spring/ripple marks actual full charge. The center stays fixed, and full cues begin at their start even after a long charging frame. No charge-time, firing or camera change. This supersedes the initial ring style below. [Evidence/limits](../evidence/2026-11-01-white-charge-tension.json).

**Charge feedback follow-up, 2026-11-01:** `Reticle` renders the crosshair and native circular charge UI in the same root. Combat supplies actual charge fraction (nil when inactive); the movement HUD positions/hides the root using the existing shared aim point. Clockwise fill, teal/gold palette and one small full cue replace the bar. Palette/geometry are centralized; customization settings remain proposed. This changes presentation only. [Evidence/limits](../evidence/2026-11-01-charge-ring.json).

Status: implemented/verified in the experimental target range, 2026-11-01; appearance/device approval open.

The owner requests a centered crosshair without a native cursor in first person/shift lock, and cursor-based aiming without a spare centered crosshair in unlocked third person. Previously the movement HUD always drew an inset-relative centered crosshair while combat always read the mouse.

Use a small movement-client `AimCursor` module as the shared source for mode and viewport-space aim position. The existing shift-lock setter updates its explicit state; first-person mode remains the existing latched choice. Locked modes use viewport center; unlocked third person uses the mouse and a custom reticle. Draw that reticle in its own IgnoreGuiInset HUD so movement debug layout is unaffected. Combat uses the same point for its ray and charge/hit feedback. Keep the existing camera-ray target/muzzle convergence and gravity; this does not add aim assistance or change projectile rules.

Settings exposes its local open state, supplementing native menu/text focus detection. Render cursor visibility after native camera and Settings cursor handling. Menus show the ordinary pointer and hide the reticle; gameplay shows one custom reticle. No camera/controller replacement, new source animation, publishing or foundation change.

Full combat verification passes. Native Studio tested each mode's reticle position and accepted server launch against its selected aim ray, plus M/Esc menu transitions and charge blocking. See [evidence/limits](../evidence/2026-11-01-aim-cursor.json). No multiplayer, touch/gamepad or subjective appearance approval is inferred.

**Appearance settings, 2026-11-01:** use a native `CrosshairStyles` module shared by Settings previews and Reticle. Seven presets and local `CrosshairStyle`/`CrosshairColor` attributes change presentation only. Fixed ink and white charge remain separate; no charge color setting. Attributes survive respawn for the session. [Evidence/limits](../evidence/2026-11-01-crosshair-settings.json).

**Checkpoint extension, 2026-11-01:** Crosshair size is a local session attribute, clamped to 75–140% and applied to the centered aiming mark only; charge ring geometry and white palette remain separate. Native gameplay pointer suppression remains a requirement after settings close and late UI writes. The owner requested this design be checkpointed on main, while source code stays in the experiment folders and not the foundation place. [Evidence/limits](../evidence/2026-11-01-crosshair-size-symmetry.json).
